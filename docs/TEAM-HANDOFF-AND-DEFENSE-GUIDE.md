# دليل تسليم فريق SAQR والاستعداد للجنة المناقشة
*(Team Handoff & Graduation Defense Playbook — Saraya Hamra University)*

هذا الدليل مكتوب خصيصاً لفريق SAQR الخمسة ليشرح **بوضوح وبساطة**:
1. لماذا أصلحنا أخطاء محددة في المشروع دون تغيير فكرة المقترح المعتمد.
2. كيف يعمل كل ملف في النظام وماذا يشرح كل عضو أمام اللجنة.
3. كيف تشغّلون المشروع خطوة بخطوة يوم العرض على جهاز 16GB RAM بدون تعليق أو أخطاء.
4. الإجابات الهندسية الجاهزة لأصعب أسئلة لجنة المناقشة.

---

## 1. أهم 7 إصلاحات أجريناها (مع الإبقاء على مقترحكم 100%)

| المشكلة في النسخة السابقة | لماذا كانت ستؤذيكم في المناقشة أو العرض؟ | الإصلاح المنفّذ في `saqr-rework` |
|---|---|---|
| **1. استخدام Wazuh `v4.7.4`** | إصدار قديم (أبريل 2024) مصاب بثغرة حرجة **`CVE-2025-24016` (CVSS 9.9 RCE)** وثغرة **`CVE-2026-40106`** في `syscheck` على ويندوز! | الترقية إلى **`Wazuh v4.14.11`** في `deploy/docker-compose.yml` مع إبقاء `wazuh.indexer` و`wazuh.dashboard` اختيارية عبر `--profile debug-ui` لتوفير **3–4GB RAM**. |
| **2. مراقبة `C:\Users` مع `report_changes="yes"` + `Event ID 23`** | كان سيمتلئ القرص في `C:\SysmonArchive`، وتتسرب محتويات ملفات المستخدمين إلى السجلات، ويمتلئ مخزن Wazuh المؤقت (500 EPS) فتضيع التنبيهات! | إزالة `report_changes="yes"` و`Event ID 23`؛ الإبقاء على `Event ID 26` مع استثناء `AppData`/`Temp`، وإضافة `Event ID 3` (SMB) و`Event ID 22` (DNS)، ورفع `client_buffer` إلى `25000 / 1000 EPS`، وحصر `FIM whodata` في `Desktop/Documents/Downloads`. |
| **3. تشغيل `ProcDump` بالتوازي مع العزل بدون تجميد العملية** | أثناء تفريغ الذاكرة تستمر الفدية بتشفير مئات الملفات وتتلف صفحات الذاكرة، وإذا انطلقت القاعدة من `vssadmin.exe` تكون العملية انتهت قبل التفريغ! | ترتيب حتمي داخل `lab/vms/saqr_contain.py`: **(1) حل PID الأب إذا كان المشغّل `vssadmin` + قائمة استثناء للعمليات الحرجة → (2) تجميد العملية (`NtSuspendProcess`) → (3) عزل Firewall مع إبقاء المنفذ 1514 و5000 → (4) تفريغ الذاكرة + `SHA-256` في خزنة `SYSTEM` ورفعها → (5) إنهاء العملية + زر `Un-Quarantine`.** |
| **4. تعارض المقترح (`Local LLM`) مع `README` (`Gemini API`)** | المقترح الموقّع ينص في العنوان والهدف #3 على **نموذج لغة محلي**، بينما `README` اعتمد Gemini السحابي! | دعم **المزوّدين معاً** في `engine/app/services/llm.py` بمتغير بيئة واحد (`LLM_PROVIDER=gemini` أو `ollama` لـ `Qwen2.5` + وضع `offline` عربي احتياطي) مع **منقّح PII إلزامي** (`redactor.py`) قبل أي استدعاء سحابي. |
| **5. غياب الربط الفعلي بين Wazuh وFastAPI** | Wazuh Indexer Alerting يفحص كل دقيقة (بطيء جداً لهدف `<5s`). | ربط فوري عبر `wazuh-integratord` (`detection/wazuh/integrations/custom-saqr.py`) موقّع بـ **HMAC-SHA256 + منع إعادة الإرسال (Anti-Replay)** يرسل التنبيه في أقل من `200ms` إلى FastAPI `:5000`. |
| **6. ادعاء "0 انتشار جانبي" بآلة ضحية واحدة فقط** | ستسألكم اللجنة: *كيف أثبتم عدم الانتشار إذا لم يوجد جهاز ثانٍ في الشبكة؟* | إضافة حاوية **`samba-canary`** خفيفة (`<64MB RAM`) لمشاركة ملفات اختبارية؛ يثبت المحاكي وصوله إليها بدون SAQR ومنعه (`0` ملفات معدّلة) مع SAQR! |
| **7. توازن العمل بين الفريق (4 أمن سيبراني + 1 هندسة برمجيات)** | وضع كل منطق الربط في Python كان سيرهق طالب هندسة البرمجيات وحده. | نقلنا منطق الربط الأولي ووسوم `MITRE ATT&CK` إلى قواعد Wazuh XML (`local_rules.xml`) التي يملكها طلاب الأمن السيبراني، وبقي FastAPI + Streamlit بسيطاً جداً (~600 سطر!). |

## 2. توزيع الأدوار في المناقشة (لكل عضو جزء واضح ومحدود)

1. **عضو المعمل والمحاكاة (Cyber):** يشرح شبكة VMware المعزولة (Host-Only)، سكريبت `win10-setup.ps1`، حاوية `samba-canary`، ومحاكي `sim_ransom.py` بأوضاعه (الهجومية + السليمة لقياس FPR).
2. **عضو الرصد وقواعد الكشف (Cyber):** يشرح `sysmonconfig-saqr.xml` (لماذا ألغينا EID 23 واستثنينا `AppData` وأضفنا EID 3 و22)، و`agent.conf` (`whodata` + `client_buffer`)، وقواعد `local_rules.xml` (`100200–100207` ووسوم `<mitre>`)، وموقّع `custom-saqr.py`.
3. **عضو الاستجابة والأدلة الجنائية (Cyber):** يشرح `soar.py` (استدعاء `PUT /active-response` عبر Wazuh API)، وترتيب `saqr_contain.py` (لماذا التجميد قبل التفريغ، قائمة العمليات المحمية، خزنة `NT AUTHORITY\SYSTEM`، تطابق `SHA-256` بين العميل والخادم، وزر `saqr_unquarantine.py`).
4. **عضو المحرك والمنصة (Software Eng. — فرج العربي):** يشرح FastAPI Core (`main.py`, `correlator.py`)، قفل منع التكرار `uq_saqr_active_incident` في PostgreSQL 16، توثيق HMAC/JWT، ومنقّح PII + تبديل `Gemini` / `Ollama` في `llm.py`.
5. **عضو لوحة التحكم والتقييم العلمي (Cyber):** يشرح لوحة `dashboard/app.py` (Streamlit RTL) وبوت `telegram.py` (وآلية Outbox عند انقطاع الإنترنت)، ونتائج التجارب الـ 20 (`metrics/run_20_trials.py` بما فيها تجربة الأنشطة السليمة FPR).

## 3. أصعب 6 أسئلة متوقعة من لجنة المناقشة — وكيف تجيبون بثقة

1. **س: لماذا استخدمتم Gemini السحابي والمقترح يقول Local LLM وخصوصية البيانات للجهات المحلية؟**
   - **ج:** بنينا طبقة AI مرنة (`LLMReportService`) تدعم كليهما بمتغير واحد: `Ollama + Qwen2.5` للبيئات المعزولة تماماً (التي تمنع خروج البيانات) و`Gemini API` مع **منقّح PII إلزامي** يحذف أسماء المستخدمين وعناوين IP وكلمات المرور قبل الإرسال، بالإضافة إلى قالب عربي حتمي يعمل دون إنترنت لضمان عدم توقف التقارير أبداً. وفي الفصل الثاني نقارن عملياً بين المحلي والسحابي من حيث الجودة والزمن والذاكرة.
2. **س: إذا كانت برمجية الفدية تعمل بصلاحية Administrator (لتشغيل `vssadmin`)، ألا تستطيع تعطيل Windows Firewall؟**
   - **ج:** ملاحظة ممتازة وموثقة صراحة في حدود نموذج التهديد (Threat Model): في الفصل الأول نستهدف برمجيات الفدية بصلاحية مستخدم عادي (حيث يرصد Sysmon EID 1 **محاولة** تشغيل `vssadmin` حتى عند فشلها بـ Access Denied، وتمنع صلاحيات النظام تعطيل الجدار أو خزنة `SYSTEM`). وفي الفصل الثاني نضيف بوابة Linux خفيفة (`nftables` + `Suricata`) لعزل خارج الجهاز (Out-of-Band) يستحيل تجاوزه حتى بصلاحية SYSTEM.
3. **س: كيف تضمنون عدم قيام النظام بعزل جهاز أو قتل عملية مهمة بالخطأ (Self-DoS / False Positive)؟**
   - **ج:** بأربع طبقات أمان: (1) قائمة عمليات محمية ثابتة داخل `saqr_contain.py` ترفض لمس `System`/`lsass`/`svchost`/`wazuh-agent`/`Sysmon64`، (2) قفل Idempotency في PostgreSQL يمنع تكرار التنفيذ، (3) اختبار 20 نشاطاً سليماً (`7-Zip`، نسخ جماعي، إعادة تسمية بنفس الامتداد، `Git`) للتحقق من `FPR ≈ 0%`، و(4) زر **Un-Quarantine** محمي بـ RBAC يعيد الشبكة فوراً بنقرة واحدة.
4. **س: كيف تمنعون نموذج الذكاء الاصطناعي من الهلوسة في أرقام MITRE ATT&CK أو التأخير في العزل؟**
   - **ج:** النموذج لا يشارك إطلاقاً في العزل (القاعدة الذهبية) ولا يخمّن معرّفات MITRE — المعرّفات تُعيّن حتمياً داخل قواعد `local_rules.xml` وتُمرّر للنموذج داخل وسم `<UNTRUSTED_TELEMETRY>` محصّن ضد حقن الأوامر (Prompt Injection).
5. **س: كيف تضمنون دقة قياس زمن الكشف `MTTD = T1 - T0` بين آلة Windows وحاوية Linux؟**
   - **ج:** عبر مزامنة وقت الآلة الافتراضية قبل كل تجربة (`w32tm /resync` + VMware Tools time sync) في `win10-setup.ps1` والتحقق من عدم وجود انحراف ساعة قبل اعتماد أي تجربة.
6. **س: لماذا ألغيتم `report_changes="yes"` و`Event ID 23` بعد المرحلة الأولى؟**
   - **ج:** لأننا اكتشفنا هندسياً أن تفعيلهما على كامل `C:\Users` يضاعف استهلاك القرص، ويسرب محتوى ملفات المستخدمين إلى السجلات، وقد يُغرق مخزن Wazuh المؤقت أثناء هجوم الفدية؛ فاستبدلناهما بـ `Event ID 26` + استثناءات `AppData` + `FIM whodata` محدود في مجلدات العمل ورفعنا `client_buffer` إلى `25000 / 1000 EPS`. *(هذه الإجابة ستُعجب اللجنة جداً لأنها تثبت نضجاً هندسياً حقيقياً!)*
